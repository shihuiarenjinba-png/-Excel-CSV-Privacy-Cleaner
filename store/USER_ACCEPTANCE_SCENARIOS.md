# Microsoft Store 登録前のユーザー受入シナリオ（合成データのみ）

対象: `improve/simple-column-ui-20261018`
目的: 非技術者が、個人情報を含む可能性のある表データを**必要な列だけ**加工して別コピーを作成できるか確認する。
これは実機の人間による受入テスト手順。実施前のステータスはすべて **未実施**。

## 前提
- 最終Git SHAを保存し、`store/verify-and-build.ps1`が生成したEXE候補を使用する。
- Windows 10/11の代表環境、日本語/英語、画面拡大100%/125%/150%、キーボード操作をそれぞれ確認。
- 使用するのは架空の顧客データのみ。実際の名前・メール・電話・住所・顧客番号は使用しない。
- 出力は専用の新規フォルダーへ。元ファイル・既存ファイルを変更していないことをSHA256で確認。
- Windows Defenderのスキャンと通信/egress検証は別工程として実施する。

## シナリオ A — 初心者のCSV加工
1. 例として列 `名前,email,部署,メモ` があるCSVを作成し、架空の3行を用意する。
2. EXEを起動し、ファイル選択→`email`だけチェック→「マスク」→プレビュー→新規保存。
3. 出力をExcelとテキストエディターの両方で開き、メールだけが置換され、ほかの列の値、先頭ゼロ、日本語、引用符、改行、空欄が保持されることを確認。
4. 保存済みのファイル名を再指定し、上書きが拒否されることを確認。
5. 確認項目: 5段階の操作が説明なしでも判断可能か、テキスト切れ・入力取り違えがないか。

## シナリオ B — Excelの複数シート
1. `People`には`email`を、`Orders`には別の列だけを設けたXLSXを作成。
2. `email`を選びマスク。結果には変更済みの`People`、指定列がなく未変更の`Orders`が明示されること。
3. 隠しシート削除とコメント削除の設定をそれぞれ確認する。
4. 出力したXLSXをExcelで開き、原本と出力の両方が正常に開けること。
5. シートが完全に安全化したと誤認させる説明がないことを確認。

## シナリオ C — 危険なExcel構造の拒否
1. 数式のあるXLSXで「列削除」を選ぶ。プレビュー時点で理由付きで拒否し、出力しない。
2. 結合セル・Excelテーブル・図形/画像/グラフを含むXLSXで処理を選ぶ。無言で壊さず、未対応を表示する。
3. 数式への影響を確認できないマスクや仮名化は拒否する。
4. できない加工を「完了」表示しないことを確認。

## シナリオ D — 仮名化
1. 架空メールアドレスの重複2件、異なる値、空欄を持つCSVを作成。
2. 同じキーは同じ仮名ID、違う値は違うID、空欄は空欄のままになることを確認。
3. 2つの異なるキーで結果が異なること、キーの表示と非表示が機能することを確認。
4. 「仮名化は匿名化・暗号化ではない」ことが製品内外の説明に書かれていることを確認。

## シナリオ E — 失敗からの回復
1. 壊れたCSV、重複列、不正な数式風のCSV値、ロック中の出力先、大きすぎるファイルを選択。
2. 原本が変更されないこと、既存ファイルが上書きされないこと、途中出力が破棄されることを確認。
3. ファイル選択に失敗した後に前の選択列や前のファイルを誤って出力できないことを確認。
4. 同じEXEで正常な合成ファイルを選び直し、再び加工できることを確認。

## 終了判定
- 各シナリオの **実行日時 / OSビルド / DPI / 言語 / EXE SHA256 / PASS・FAIL・SKIP / 証拠ファイル** を保存。
- エラー表示の分かりにくさ、クリックできないボタン、処理中のフリーズは修正対象として記録。
- 失敗・未確認項目をPASSへ変更しない。
- すべての受入テストに合格しても、プライバシー通信監査・第三者ライセンス・商品名権利・販売価値・Microsoft Store審査は別のゲート。
